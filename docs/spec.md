# 로컬 가계부 — 설계 문서

## 1. 제품 성격

혼자 쓰는 개인용 모바일 PWA 가계부. 모든 지출을 기록하는 것이 목적이 아니라
**월급 분배 룰**과 **혜택·특가 소비 플랜**에 집중한다.

접근성(a11y), 테스트 커버리지, 린터, 다중 사용자 대응은 의도적으로 범위 밖에 둔다.
단 **데이터 유실 방지는 예외** — 사용자가 한 명이라 백업본이 사용자밖에 없고,
localStorage가 유일한 저장소이기 때문이다.

## 2. 저장소 구조

| localStorage 키 | 내용 |
| --- | --- |
| `LOCAL_LEDGER_DATA_V3` | 가계부 본체 (`AppState`: deals / salaryConfig / quickTags) |
| `LOCAL_LEDGER_BROKEN_<ts>_<rand>` | 읽지 못한 손상 데이터 스냅샷 |
| `LOCAL_LEDGER_PREIMPORT_<ts>_<rand>` | 복원·초기화로 교체되기 직전 스냅샷 |
| `LOCAL_LEDGER_AI_CONFIG` | AI 설정 (API 키, 모델명) — **가계부 본체와 분리** |

스냅샷은 최근 5개까지만 유지한다 (용량 폭주 방지).

## 3. 백업 안전 규칙

- 내보내기 파일에는 `app: "local-ledger"`, `schemaVersion`, `exportedAt` 헤더를 찍는다
- 복원은 **검증 → 사용자 확인 → 교체 직전 스냅샷 → 적용** 순서를 반드시 지킨다
- `deals` 배열과 `salaryConfig` 객체가 없으면 복원을 거부한다
  (엉뚱한 JSON이 기존 기록을 빈 상태로 덮어쓰는 사고를 막기 위함)
- **API 키는 백업 파일에 절대 포함하지 않는다.** 별도 localStorage 키에 두는 이유가 이것이다.
  백업 파일을 공유·업로드해도 키가 새지 않아야 한다

## 4. 월급 룰

### 4.1 차감 합계가 월급을 넘어도 막지 않는다

차감 항목 금액에는 **하한(0)만 두고 상한을 두지 않는다.** 합계가 월급을 넘으면
'남은 금액'이 음수로 빨갛게 표시될 뿐 입력은 그대로 저장된다.

**의도된 동작이므로 검증을 추가하지 말 것.** 이유:

- 포인트·앱테크 같은 **월급 필드에 잡히지 않는 부수입**으로 메우는 경우가 있다
- 월급을 넣기 전에 차감 항목부터 적어두는 흐름을 막지 않기 위함

## 5. AI 연동 (Gemini)

### 5.1 결정 사항

| 항목 | 결정 |
| --- | --- |
| 제공자 | Google Gemini (Developer API) |
| 기본 모델 | `gemini-3.8-flash` (설정에서 변경 가능) |
| 대체 모델 | `gemini-3.7-flash` (설정에서 변경·해제 가능) |
| 엔드포인트 | `https://generativelanguage.googleapis.com/v1beta` |
| 인증 | `x-goog-api-key` 헤더 (쿼리 파라미터 `?key=` 대신 — URL·로그 유출 방지) |
| 기본 상태 | **꺼짐.** 키를 넣어야만 동작 |
| 요금제 | 무료 티어 전제. 한도 초과 시 대체 모델을 시도하고, 그래도 안 되면 오류를 표시 |

CORS 확인 완료: preflight가 `x-goog-api-key`를 허용하고, GitHub Pages 오리진에
`Access-Control-Allow-Origin`이 응답된다. 별도 프록시 서버가 필요 없다.

### 5.2 키 취급 원칙

localStorage 저장은 서버가 없는 구조에서 유일한 선택지이며, **안전하다는 뜻은 아니다.**
전제와 완화책:

- **결제 미연결 무료 키를 쓴다.** 유출되어도 금전 피해가 없고 한도만 소모된다 (가장 중요)
- Google AI Studio에서 키에 API 제한(Generative Language API 한정)을 건다
- 입력란은 `type="password"`, 화면에는 마스킹된 형태로만 표시
- 언제든 삭제 가능
- **외부 스크립트를 앱에 들이지 않는다.** 현재 외부 스크립트가 0개라 XSS로 키가
  새어나갈 실질 경로가 없다. 이 조건이 깨지면 위 전제가 무너진다

### 5.3 기능 로드맵

1. **설정 화면 (키 관리)** — 완료. 키 저장·삭제·연결 테스트.
   연결 테스트는 `GET /models`를 쓴다 (생성 쿼터를 소모하지 않고 키와 모델명을 동시에 검증)
2. **한 줄 입력에 AI 모드 추가** — 완료.
   `POST /models/{model}:generateContent` + `generationConfig.responseSchema`로 JSON을 강제한다.
   전송 데이터는 입력 문장과 태그 목록뿐이며 **월급·저축 정보는 보내지 않는다.**
   입력 모드는 5.6 참고
3. **혜택 안내/영수증 스크린샷 인식** — 이후. 이미지는 토큰 소모가 커 한도를 빨리 쓴다
4. **이달 소비 리뷰** — 보류. 한 달치 데이터를 통째로 보내야 해서 프라이버시 대비 가치가 낮다

### 5.4 산술은 AI에게 맡기지 않는다

LLM은 곱셈·퍼센트 계산에서 틀린다. 그래서 AI에게는 **문장에서 읽어낸 조각만** 내놓게 하고
금액 계산은 앱 코드가 한다.

| AI가 내놓는 것 | 앱이 계산하는 것 |
| --- | --- |
| `unitPrice`, `quantity`, `totalPrice` | `finalPrice = totalPrice > 0 ? totalPrice : unitPrice × quantity` |
| `benefitPercent`, `benefitAmount` | `benefitAmount = percent > 0 ? round(finalPrice × percent / 100) : amount` |

예) "빕스 3인 인당 49700원, Tday 40프로 적립"
→ AI: `{unitPrice: 49700, quantity: 3, benefitPercent: 40, benefitType: "point_reward"}`
→ 앱: 결제 149,100원 · 적립 59,640원

계산 근거 문자열(`49,700원 × 3 = 149,100원 · 40% 적립 = 59,640원`)을 만들어
입력 화면과 메모에 함께 남긴다. 사용자가 눈으로 검산하고 저장하도록 하기 위함이며,
나중에 기록을 다시 봐도 금액의 근거를 알 수 있다.

`instant`는 결제 금액에 이미 할인이 반영된 것으로 보므로 `benefitAmount`를 0으로 강제한다.

### 5.5 모델 폴백

기본 모델이 실패하면 대체 모델로 한 번 더 시도한다. **단 실패 종류를 가린다.**

| 상태 | 폴백 | 이유 |
| --- | --- | --- |
| 404 | 한다 | 모델 은퇴·오타. 대체 모델이 없으면 AI 입력이 통째로 막힌다 |
| 429 | 한다 | 무료 한도는 모델별로 잡히므로 대체 모델에 여유가 있을 수 있다 |
| 5xx | 한다 | 모델별 용량 문제 |
| 응답 파싱 실패 | 한다 | 모델이 스키마를 어긴 경우라 다른 모델은 지킬 수 있다 |
| 400 / 403 | 안 한다 | 키 문제라 모델을 바꿔도 같은 오류. 재시도는 낭비 |
| 네트워크·타임아웃 | 안 한다 | 마찬가지 |

**폴백이 일어나면 어떤 모델이 응답했는지 화면에 표시한다.** 조용히 대체 모델로
돌아가면 기본 모델이 은퇴한 사실을 몇 달간 모르게 된다.

대체 모델을 비워두면 폴백하지 않는다.

### 5.6 입력 모드 — AI 실패를 정규식으로 감추지 않는다

한 줄 입력은 **기본(정규식)**과 **AI** 두 모드로 나뉘고, 열 때마다 기본이 선택된다.

- **기본**: 정규식 파서. 네트워크·키 없이 항상 동작한다. 숫자를 나열한 입력에 강하다
- **AI**: Gemini. 개수·퍼센트·상대 날짜 같은 문장형 입력을 처리한다

**AI가 실패하면 정규식으로 자동 전환하지 않고 오류를 그대로 보여준다.**
두 파서의 결과 품질이 전혀 달라서, 조용히 넘기면 사용자가 엉뚱한 값을 저장하게 되기 때문이다.
같은 문장을 두 파서에 넣으면 이렇게 갈린다:

```
입력: 빕스 3인 방문했는데, 인당 49700원이었어, Tday 40프로 적립을 했으
AI  : 결제 149,100원 · 적립 59,640원
정규식: 결제 3원 · 혜택 49,700원   ← "3인"의 3을 금액으로 읽음
```

오류 안내에는 '기본 입력으로 전환' 버튼을 함께 띄워 사용자가 직접 고르게 한다.

저장은 폼에 보이는 값만 쓴다. 등록 시점에 입력 문장을 다시 파싱하지 않는다
(사용자가 눈으로 확인한 값과 저장되는 값이 달라지면 안 된다).

### 5.7 금지 사항

- **실시간 할인·특가 정보를 물어보는 기능은 만들지 않는다.**
  Gemini에는 실시간 행사 데이터가 없어 존재하지 않는 행사를 지어낸다.
  가계부에서 이는 단순 오답이 아니라 헛돈을 쓰게 만드는 오답이다
- **AI가 데이터를 직접 쓰지 않는다.** 항상 폼에 채워 넣고 사용자가 확인한 뒤 저장한다

### 5.8 문서 정합성

AI 기능을 켜면 데이터 일부가 Google로 전송되므로, README의
"Zero Server / 100% 로컬" 문구는 "AI 기능은 기본 꺼짐이며, 켰을 때 무엇이 전송되는지"를
명시하도록 수정해야 한다.
